# 现金流量表主表工作底稿

## 🌟 这是什么

这是一个在 Windows 电脑上使用的现金流量表主表编制技能。它采用工作底稿法，根据审定资产负债表、审定利润表、科目余额表和已经拆分好的一借一贷明细，自动计算本期现金流量表主表，并同时生成一张可以逐项复核的计算验证底稿。

最终得到的不是一张来源不明的结果表，而是一个包含两张可见工作表的电子表格文件：

- “现金流量表”是可以直接查看和进一步复核的正表。
- “计算验证底稿”展示每个正表项目由哪些金额组成、数据来自哪里、为什么加减、是否涉及非现金事项、是否存在未解释差异，以及正表金额是否与底稿反算结果一致。

技能尽量自动完成取数、分类、计算、勾稽和异常判断。只有金额重大且现有证据确实互相冲突时，才需要人工确认。

## 🏢 适用于哪些企业

当前支持制造、商贸、服务等一般企业，以及银行、证券公司、保险公司和其他金融企业的单体现金流量表。系统会根据报表项目、科目名称和期间判断企业类型。保险公司会进一步识别适用的报表格式，现行保险报表的每个现金流项目都有独立核验记录。

本技能暂不处理：

- 合并现金流量表及合并抵销。
- 按现金类序时账逐笔标注现金流项目的直接法。
- 把原始多借多贷凭证重新拆成一借一贷明细。
- 现金流量表补充资料。

## 📦 使用前要准备什么

### 1. 审定资产负债表

资产负债表应包含期末和期初两个时点。这里不是要求提供两张资产负债表，而是使用正常资产负债表中的本期时点数和上期时点数。最少应能识别报表项目名称、期末金额和期初金额。

### 2. 审定利润表

利润表应为本期审定后的报出金额，最少应能识别报表项目名称和本期金额。

### 3. 本期科目余额表

科目余额表用于生成账面报表、核对序时账和分析报表项目变动。最少应包含科目编码、科目名称、期初余额、本期借方发生额、本期贷方发生额和期末余额。

科目余额表不必预先与审定报表完全一致。技能会先根据科目余额表生成账面报表，再与审定报表逐项目比较，自动计算账表差额。

### 4. 已拆分好的一借一贷明细

这份文件来自序时账分析工具。每一行应当已经是一个明确的借方科目、一个明确的贷方科目和一个对应金额，不会再出现一行对应多个对方科目的情况。

本技能新增的最低要求只有借方科目名称、贷方科目名称和配对金额。日期、凭证号、摘要等原有字段如果存在，应当保留，它们可以提高自动判断的准确性。技能不要求额外添加分录行号、本方分录编号、对方分录编号或重复提供科目编码。

“现金流标签”不是必填字段。如果文件中已经有现金流标签，系统会把它当作提示信息，同时结合借贷科目和摘要独立判断。标签与实际业务关系冲突时，底稿会同时列出自动判断、原标签和冲突原因，不会盲目相信原标签。

### 5. 上年度审定现金流量表

这份文件只用于搬取正表的上期金额。本技能不会重新计算上期组成。系统会按项目名称匹配上期数；没有匹配成功的项目会在计算验证底稿中列出，并暂按零填列。

### 6. 实际执行重要性水平

还需要输入本项目的实际执行重要性水平，单位为元。这个金额用于决定哪些业务性质冲突可以自动采用最合理的判断，哪些重大冲突必须留给人工确认。

### 可以提供但不是必须提供的资料

账表调整明细和审计调整明细有就提供，没有也可以先运行。提供时最少包含调整编号、报表项目和调整金额，调整性质可以不填。

如果没有提供，系统不会把寻找差额的工作推回给客户，而是自行比较“科目余额表生成的账面报表”和“审定报表”，先算出每个报表项目的差额，再根据金额、科目关系和业务证据形成候选判断。只有重大且性质确实无法唯一判断的事项，才进入待确认清单。

## 🖱️ 实际怎么使用

在对话中说明要使用“现金流量表主表工作底稿”技能编制现金流量表。技能启动后会弹出 Windows 文件选择窗口，不需要手工输入长路径。

窗口会依次要求选择或填写：

1. 审定资产负债表。
2. 审定利润表。
3. 科目余额表。
4. 一借一贷明细。
5. 上年度审定现金流量表。
6. 是否提供账表调整明细。
7. 是否提供审计调整明细。
8. 输出文件夹。
9. 实际执行重要性水平。
10. 编制单位名称。
11. 所属期间，例如“2025年度”。

如果某次选择错了，可以取消本次选择并重新开始。取消时不会留下半套正式运行结果。

## ⚙️ 系统会怎样计算

### 第一步：读取和检查文件

系统只读原始文件，不改动客户提供的工作簿。金额统一转换为最小货币单位运算，避免小数计算误差。

默认只读取可见工作表。只有可见工作表中的公式明确引用了隐藏工作表时，才读取被引用的隐藏工作表；其他隐藏工作表不参与计算。

如果输入单元格是公式，文件中必须保存有公式计算结果。公式只有表达式却没有已保存结果时，系统会指出具体文件、工作表和单元格，不会把空结果当成零。

### 第二步：核对一借一贷明细与科目余额表

系统先按科目汇总一借一贷明细的借方和贷方金额，再与科目余额表发生额核对。

如果一借一贷明细使用总账科目，而科目余额表使用多个明确的下级明细科目，系统会在能够唯一判断时自动汇总下级科目进行核对。若一个科目可能对应多个互不相关的科目，或者金额仍然不一致，则停止后续正式计算并列出差异。

### 第三步：生成账面报表并寻找账表差额

系统根据科目余额表和报表项目映射生成账面资产负债表、账面利润表，再与审定报表逐项目比较。每个项目都保留账面数、账表调整、审计调整、审定数、总差额和尚未解释的差额。

常见标准科目会自动归集到报表项目。例如，原材料、库存商品、生产成本等可以汇总到“存货”；库存现金、银行存款和其他货币资金可以汇总到“货币资金”。如果一个科目同时可能落入两个不同报表项目，系统会阻塞并明确提示需要修正的映射关系。

### 第四步：确定现金及现金等价物范围

系统根据科目名称、期限和可使用状态识别现金范围：

- 冻结、质押、保证金、监管资金、不可随时支取资金等从现金及现金等价物中剔除。
- 明确超过三个月的定期存款默认剔除。
- 只写“定期存款”但没有期限和可支取条件的，不会直接当成现金。系统先按剔除处理并形成判断记录；金额重大且证据冲突时才要求人工确认。
- 明确在三个月以内、流动性强、可随时用于支付且价值变动风险很小的，才可能作为现金等价物。

计算验证底稿会列出期初和期末的现金范围剔除明细，便于检查受限资金及定期存款处理。

### 第五步：建立统一计算资料

系统把审定报表金额、科目余额变动、账表调整、审计调整和一借一贷明细转换成同一种可追溯的计算资料。

确定性业务会直接形成对应调整，例如长期资产购建与处置、工程和设备预付款、取得或处置营业单位、投资、借款、偿债、利息、股利、政府补助、税费返还、罚款、非现金取得资产、应收应付抵销、债务重组以及汇率变动影响。

日常销售、采购、职工薪酬等已经由工作底稿公式覆盖的业务，不会因为一借一贷明细中再次出现而重复计入现金流。

### 第六步：逐项目计算现金流量表

系统按现金流量表项目逐项计算，并记录每一个组成金额的来源、加减方向和占用状态。

净额项目会自动处理正负方向。例如：

- 处置长期资产的现金净额为正数时列入处置长期资产收回的现金净额，为负数时转入支付其他与投资活动有关的现金。
- 处置营业单位的现金净额为负数时，转入支付其他与投资活动有关的现金。
- 取得营业单位支付的现金扣除取得时带入的现金后，如果成为净现金流入，转入收到其他与投资活动有关的现金。
- 正好抵销为零时，相关组成仍保留在底稿中，并且只占用一次。

长期资产购建项目按实际付现事实汇总。非现金取得长期资产不会被错误扣成负现金流，应付款和预付款余额变动也不会与已经取得的实际付现额重复叠加。

### 第七步：完整性检查

系统会检查应当分配的金额是否遗漏、同一个金额是否重复使用、各活动小计和净额是否勾稽、本期现金净增加额是否与期初期末变动一致，以及是否存在无法分类的现金收付。

未分类现金不会藏在内部记录里。计算验证底稿会直接列出事实编号、借方科目、贷方科目、金额、来源和现有判断依据。

## 🤖 自动判断与人工确认

系统遵循“能自动解决就自动解决”的原则：

- 业务性质明确时，直接按规则计算。
- 金额低于实际执行重要性水平时，采用证据最强的首选判断并留下记录。
- 金额虽然重大，但不存在两套相互矛盾且都有充分依据的解释时，仍采用唯一首选判断。
- 只有“金额达到实际执行重要性水平”和“存在强冲突”两个条件同时满足时，才要求人工确认。

即使需要确认，系统仍会先按证据最强的首选判断生成完整暂编表，便于整体复核。重大事项确认完成前，暂编表不能改成最终表。

账务不平、漏项、重复占用、现金变动不平不属于人工判断事项。这些属于计算或输入异常，系统会直接阻断并列出差异，不会让人工猜一个数把表强行做平。

## 📊 输出文件怎么看

输出电子表格固定只有两张可见工作表，没有隐藏工作表，也没有外部链接。

### “现金流量表”

- 本期金额来自本次工作底稿计算。
- 上期金额从上年度审定现金流量表搬取。
- 本期和上期金额都是冻结数值，打开文件时不依赖其他工作簿重新计算。
- 正表项目可以跳转到计算验证底稿中的对应项目。
- 没有财政部正式行次来源的项目，行次留空，不用内部编号冒充正式行次。

### “计算验证底稿”

底稿包含：

- 编制状态和完整性检查结论。
- 账面数、账表调整、审计调整、审定数和未解释差额组成的账表调整桥。
- 没有匹配到报表项目的科目。
- 自动判断事项及其支持证据、相反证据、候选方案和确认状态。
- 现金范围剔除明细，包括受限资金和不符合条件的定期存款。
- 未分类现金明细。
- 一借一贷明细与科目余额表的核对差异。
- 每个现金流项目的组成编号、来源项目、原始金额、加减方向和计入金额。
- 非现金剔除、特殊事项调整和现金范围处理说明。
- 自动分类依据、原文件中的现金流标签及标签冲突。
- 规则计算结果、正表列示金额、验证差异和核对结论。
- 上期项目名称没有匹配成功的清单。

验证底稿使用当前工作簿内部公式反算正表金额。公式只是为了让复核人员看得见、点得开、算得回，不是把正式计算过程临时塞进电子表格。程序计算结果和底稿展示使用同一份冻结数据。

## 🚦 三种运行结果

### ✅ 最终

账务核对、项目计算、完整性检查全部通过，并且没有尚未确认的重大冲突。可以输出最终正表和计算验证底稿。

### 🟡 暂编

主体计算已经完成，但行业、保险格式或重大业务性质仍有强冲突需要确认。暂编表会完整列出首选金额和待确认事项，但不能冒充最终表。

### 🛑 阻断

存在账务不一致、科目映射不唯一、金额漏分、重复占用、小计不平或现金变动不平。此时先根据差异明细修正输入或映射，再重新运行。

程序遇到无法读取的文件、缺少必要字段或公式没有保存结果时，会保留中文错误说明和本次输入清单，便于定位，不会只显示一个无法理解的失败标志。

## 🧭 常见问题

### 科目余额表和审定报表不一致，还能用吗？

可以。发现并解释账表差异本来就是本技能的工作之一。账表调整明细和审计调整明细有则使用，没有则先由系统自行计算差额。

### 一借一贷明细一定要有对方科目吗？

要有明确的借方科目和贷方科目，因为这就是已经拆分完成的一借一贷关系。不需要再提供一个额外的“对方科目”字段，也不需要本技能重新分析多借多贷凭证。

### 必须先给每笔业务标现金流项目吗？

不需要。现金流标签不是必填项。系统根据报表、余额表、借贷科目、摘要和工作底稿规则进行判断。

### 没有账表调整明细或审计调整明细怎么办？

可以先运行。系统会自己计算账面报表与审定报表的差额，并尽量自动解释。只有重大且存在强冲突的性质判断才需要补充确认。

### 为什么一定要上年度现金流量表？

因为本期正表需要列示上期金额。本技能只搬取上年度审定现金流量表的金额，不重新编制上期现金流量表。

### 为什么有些定期存款被剔除了？

定期存款不能仅凭科目名称自动认定为现金等价物。系统需要结合期限、流动性、可支取条件和价值变动风险判断。信息不足时先按剔除处理，并在底稿中留痕。

### 为什么输出里既有正表又有底稿？

只有正表无法说明数字从哪里来，也无法发现漏项、重复和错误调整。计算验证底稿就是整个计算过程的可见版本，用于逐项目反算、复核和验证。

## 🔒 原始资料和运行结果

原始文件只读，不会被改写。每次运行会记录五个固定输入文件的校验信息。后续确认前如果原始文件发生变化，系统会要求重新准备运行，防止用旧计算结果配新资料。

所有结果写入用户选择的输出文件夹。运行资料包括正表、计算验证底稿、账务核对结果、逐组成计算记录和判断留痕，便于后续复核。
